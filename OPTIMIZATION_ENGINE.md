# Optimization engine

The demo uses a customer-contextualized Beta-Bernoulli Thompson sampler. Every eligible customer/action arm stores positive mass `alpha`, negative mass `beta`, and a feedback count `n`. New priors derive from heuristic intent, churn, price sensitivity, engagement, and order history. For selection, the app draws a Beta posterior sample and ranks `0.80 × sample + 0.20 × context prior`. Eligibility also uses consent and context: targeted offers require high sensitivity, a long activity gap, and the local 14-day recommendation cap; loyalty rewards require repeat history; support check-ins require elevated heuristic churn. “No action” remains eligible.

Feedback is simulated. A positive/no-response response determines a bounded fractional reward from response, engagement proxy, order-value contribution proxy, retention value, customer-experience proxy, and discount cost for an offer. The app adds `reward` to alpha and `1 - reward` to beta for the selected arm. “Run 5 simulated rounds” samples outcomes from posterior means, applies the same fractional reward formula, and persists the resulting state. The values are demo proxies, not measured revenue or conversion. Browser local storage retains parameters. Local JSON server storage retains them across restarts; Vercel server sync uses temporary instance-local storage. Event records contain the simulated outcome and reward, not message text.

Production use would need logged exposure and actual outcome attribution, a validated reward window, exploration safeguards, frequency caps, consent enforcement, holdouts, minimum sample thresholds, and human approval before external delivery. No campaign is connected and no discount is issued by the demo.
